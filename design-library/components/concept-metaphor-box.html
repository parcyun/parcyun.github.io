MCP Model Context Protocol

제각각인 API 활용 방식을 통합해주는 "단일 표준 규격". MCP 규격을 따르는 프로그램끼리는 연결이 매우 간단하고, 활용 방식이 규격화되어 오류가 적고 최적화도 잘 되어 있습니다.

Metaphor

"범용 어댑터" or "만능 통역기"

라이트닝 어댑터, USB-A, HDMI, RGB, AUX 등 여러 종류의 단자가 난무할 때 등장한 USB-C처럼, MCP는 LLM ↔ 외부 도구 연결의 USB-C입니다.

Usage

1. .concept + .metaphor-box CSS 블록 복사
2. 두 블록을 함께 사용 (정의 + 비유 = parcyun 교육 핵심 패턴)

STRUCTURE:
.concept (정의)
├─ .concept-title       대형 한 단어 또는 영문 약자 (Bold 700)
│  └─ small             영문 풀네임 또는 부제 (Light 300, secondary 색)
└─ .concept-def         정의 문장 1-2개

.metaphor-box (비유 — 안정성 원칙: 일상 사물로 비유)
├─ .label "METAPHOR"    캡스 라벨
├─ .name                일상 사물 이름 (amber, "따옴표" 안에 표현)
└─ .desc                왜 비유가 적절한지 설명 (1-3 문장)

PARCYUN 비유 가이드 (이미 사용된 매칭):
- API     → "점원 & 키오스크"
- Skills  → "레시피"
- MCP     → "USB-C 어댑터"
- Harness → "대기업 본부 사무실"
- Orch.   → "팀장 / PM"
원칙: 가전제품, 자동차, 건축, 학교, 도시 구조 등 일상에 빗대기

WHEN TO USE:
- 추상적 기술 개념 설명
- 처음 듣는 용어 소개
- 학습자가 직관적으로 이해해야 하는 핵심 개념

WHEN NOT TO USE:
- 이미 익숙한 개념 (반복 학습)
- 단순 정의만 필요한 경우 (.concept만 사용)
- 비유가 오히려 혼란을 줄 정도로 복잡한 개념
