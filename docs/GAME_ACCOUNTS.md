# 게임 계정 연결

## 배포 구성

- Google Cloud / Firebase 프로젝트: `parcyun` (`1093702239224`).
- 로그인: Firebase Authentication / Google 공급자, 공개 이름 `parcyun studio`.
- 허용 도메인: `parcyun.github.io`, `parcyun.firebaseapp.com`, `parcyun.web.app`, `localhost`, `127.0.0.1`.
- 프로필: Firestore `(default)`, 서울 `asia-northeast3`, `profiles/{Firebase UID}`.
- 별명·선택 학교·선택 사진·수정 시각만 프로필 문서에 저장. Google 실명을 기본 별명으로 복사하지 않는다.
- 프로필 사진은 브라우저에서 128×128 WebP로 변환해 저장한다. 외부 업로드 버킷은 사용하지 않는다.
- 개인 기록은 브라우저에 남고, 로그인 후 스펠 드릴 결과 화면 또는 랭킹 하단의 `기록 제출`을 선택하면 서버 최고 기록이 공개 랭킹에 저장된다.
- `spellBoards/{언어}_{난이도}_{모드}/players/{UID}`: 별명·선택 학교 이름·점수·소요 밀리초·실제 플레이 시각·서버 수정 시각만 저장한다. 학교는 새 기록 제출 시에만 공개하며 기존 프로필을 소급 공개하지 않는다. 사진·이메일은 공개하지 않는다.
- 점수 내림차순·소요 시간 오름차순. 50개씩 커서 페이지를 추가하고, 내 순위는 전체 서버 집계로 계산하므로 첫 페이지 밖에서도 정확하다. 완전 동점은 공동 순위다.
- 기존 로컬 기록의 자동 이관은 하지 않는다. 결과가 낮거나 같은 경우 서버 최고 기록과 날짜를 덮어쓰지 않는다.
- Simplification: 점수는 클라이언트 계산값이며 소유자·필드·범위·날짜·최고 기록 갱신만 서버 규칙으로 제한한다. 경쟁 대회·상품 제공을 시작하기 전 서버 발급 라운드와 정답 검증 방식으로 업그레이드해야 한다.
- Firebase 웹 API 키와 앱 ID는 공개 클라이언트 설정이다. 비공개 관리 자격 증명은 사이트에 포함하지 않는다.

## 서버 접근 제한

`firebase/firestore.rules`는 본인 프로필만 조회·생성·수정·삭제할 수 있게 한다. 공개 랭킹은 누구나 조회할 수 있지만 기록 생성·갱신·삭제는 본인만 가능하다. 다른 경로는 허용하지 않는다. 필드 목록·자료형·길이·수정 시각을 서버 규칙에서 검사한다.

규칙 재배포: 인증된 Mac에서 `node scripts/deploy-game-profile-rules.mjs` 실행. 스크립트는 `gcloud`의 현재 로그인 자격으로 `parcyun`에만 배포한다.
랭킹 인덱스: `node scripts/deploy-spell-ranking-index.mjs`. `score DESC / elapsedMs ASC`, collection scope, READY 후 조회 검증.

## 지오웹 크기 비교·랭킹 (2026-10-29)

- 평면·지구본·어안뷰 모두 실제 크기 비교를 지원한다. 구면 뷰는 국가 복사본을 회전 이동하여 크기를 보존한다. 복사본 히트 테스트로 드래그를 구분하며, 배경 드래그는 기존 지도 조작을 유지한다.
- 국기 195개를 idle 시점부터 4개씩 낮은 우선순위로 미리 캐시한다. 게임 중 공용 서비스 이동 도구를 숨기고 게임 마치기를 푸터 위에 배치하며 모바일 정답 입력 영역과 간격을 둔다.
- 좌측 게임 목록 오른쪽 랭킹 버튼과 결과 화면의 기록 제출을 추가했다. geoBoards/{게임 종류}/players/{UID}에 로그인 후 직접 제출한 최고 기록만 공개한다. 연습 모드는 제출하지 않는다. 별명·선택 학교·점수·소요 밀리초·플레이 시각·서버 수정 시각만 저장한다. 기존 로컬 기록을 자동 공개하지 않는다.
- 기존 players 복합 인덱스 READY와 서버 규칙 배포를 확인했다. 세 뷰의 복사본 이동/지도 고정 및 배경 드래그 이동, 1200px·390px에서 게임 마치기 클릭, 비로그인 전체 랭킹 조회·국기 캐시를 브라우저로 확인했다. 관련 테스트 17개 통과.
- 남은 검증: 실제 Google 로그인 계정으로 게임 종료 → 기록 제출 → 내 순위 재조회. 비로그인에서는 실제 랭킹 쓰기를 수행하지 않았다.

- 지오웹 랭킹은 스펠 드릴과 같은 하단 90dvh 시트로 표시하며 열릴 때 아래에서 올라온다. 게임 선택 드롭다운을 제거하고 모달 좌측에 6개 게임 목록을 고정했다. 작은 화면에서도 좌측 목록과 우측 순위표를 유지하며 각 영역을 스크롤한다. 모션 감소 설정에서는 등장 애니메이션을 생략한다.
- 하단 랭킹 시트 검증: 1200px·390px에서 하단 정렬·좌측 게임 전환·드롭다운 제거·가로 넘침 없음·ESC 포커스 복귀 확인. 모션 감소 설정에서 애니메이션 없음 확인. 빌드 및 관련 테스트 7개 통과.

## 지오웹 게임 난이도·내 기록 (2026-10-29)

- 1~4번 게임을 선택하면 초급·중급·고급 중 하나를 고른 뒤 시작한다. 두 수도 게임의 기존 쉬움/어려움 명칭과 국가 정보 제공 차이를 유지한다. 새 초급/중급/고급은 출제 국가의 친숙도 설정이다. 5~6번의 고정 난이도는 유지한다. 선택 난이도를 기본 점수에도 적용한다.
- geoGameDifficulty.js의 국가 친숙도 분류는 한국 교실을 가정한 편집 기준이며 통계적 인지도 순위가 아니다. 초급/중급/고급에서 해당 친숙도 군의 추첨 비중은 80/70/80%다. 12개씩 중복 없이 뽑되, 다음 묶음은 다시 가중 추첨하여 긴 게임에서도 비중을 유지한다. 직전 문제의 즉시 재등장을 피한다.
- 로컬 기록 키와 서버 보드는 1~4번에 한해 {mode}_{easy|med|hard}로 분리한다. 기존 난이도 미분류 데이터는 변경하지 않고 랭킹 상단의 이전 기록에서 조회한다. 기존 캐시 클라이언트의 기본 경로도 호환한다.
- 결과 화면의 랭킹·기록 제출 버튼은 다른 동작 아래 별도 줄의 중앙으로 이동했다. 랭킹 상단에 난이도 선택, 하단에 선택한 게임·난이도의 내 최고 기록 강조 박스를 추가했다. 제출 기록의 난이도를 별도로 명시하고 실제 제출 버튼도 중앙에 둔다.
- 검증: 가중 추첨·기록 분리·기존 기록 보존·서버 경로·점수 관련 테스트 13개 통과. 브라우저에서 1~4번×3단계의 12개 조합 모두 실제 정답→점수→종료·난이도 기록을 확인했다. 12개 랭킹 조회 오류 없음. 1200px·390px에서 상단 난이도, 하단 박스, 제출 버튼의 독립 중앙 줄을 확인했다. 내 순위 수치 표시는 로컬 모의 응답으로 확인했고, 비로그인 실제 제출은 로그인 요구로 차단됨을 확인했다.
- 미검증: 실제 Google 로그인 계정으로 새 난이도 기록 제출 후 서버 내 순위 재조회. 다음 확인: 원하는 게임·난이도로 로그인 플레이 후 기록 제출→동일 난이도 랭킹의 내 기록 박스 조회.
