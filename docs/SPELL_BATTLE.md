# Spell Drill 대항전

2026-11-17 라이브 구현. 정적 화면은 기존 GitHub Pages 배포를 사용하고 방 API는 Cloud Run `parcyun / asia-northeast3 / spell-drill-battle`을 사용한다. API 주소는 `public/spell-drill/battle/config.json`에 있다.

## 동작

- 브라우저 프로필 또는 Google 로그인 확인 후 입장한다. 라이브 API는 Firebase ID 토큰을 검증하고 6시간 유효한 대항전 세션을 발급한다. 브라우저 프로필은 UID와 프로필 버전별로 구별하며, 방에 입장한 시점의 별명을 저장한다. 별도의 서버 프로필을 만들거나 연동하지 않는다.
- 게임을 만들 때 팀전과 개인전을 선택한다. 진행자는 플레이어에 포함되지 않는다. 팀전은 2~10개 팀을 설정하고 참여자는 인원이 적은 팀 중 무작위로 배정된다. 진행 전 팀 이동·내보내기·팀 수·난이도·시간·라운드를 설정한다. 이동한 사람은 팀 목록 맨 아래로 간다.
- 개인전에는 팀 정보·팀 이동·팀 이름이 없다. 전원이 같은 난이도·시간·라운드로 플레이하며 개인별 점수와 순위를 집계한다. 진행자는 개인별 실시간 리더보드, 참여자는 자기 누적 점수와 종료 후 개인 순위를 본다.
- 팀의 첫 번째 참여자가 팀 이름을 바꾼다. 준비 완료한 참여자의 카드는 잠기고 팀원 전원이 준비하면 팀 이름도 잠긴다. 설정이 바뀌면 준비가 취소된다. 참여자 두 명 이상, 전원 준비 후 시작한다.
- 진행자는 실시간 팀 리더보드, 참여자는 자기 팀과 답안 화면을 본다. 개인전 풀이 화면 하단에는 내 점수 카드를 반복 표시하지 않는다. 순위 변경 시 카드가 이동하며 1위는 큰 호박색 카드로 표시된다. 라운드 사이 10초 카운트다운 후 자동으로 다음 라운드가 시작된다.
- 팀 상자는 상단 강조선 없이 테두리와 내부 배경색으로 구분하고, 순위가 바뀌어도 팀별 색을 유지한다.
- 준비 전 참여자 이름 박스는 정상 색으로 보이는 비상호작용 요소이며, 준비 완료 시 초록 체크와 비활성 색을 표시한다. 이름 옆 이동 화살표와 대항전 내부의 대기 커서를 제거했다. 진행자는 준비 전 이름을 눌러 관리하거나 드래그로 이동한다.
- 대기실은 브라우저 높이에 맞춘 고정 상단·하단과 독립된 목록 스크롤 영역으로 구성하며 스크롤바를 숨긴다. 참여자에게 상단 게임 설정을 표시하지 않는다. 명단 갱신이나 준비 상태 변경 시 목록 스크롤 위치를 보존한다.
- 준비 화면·리더보드 중앙 상단에 참여 코드를 표시한다. 진행자는 대기실 중앙 하단의 `대항전 종료하기`에서 확인 후 방을 닫으며, 참여자에게 종료 안내를 표시하고 기존 코드 재참여를 막는다. 경기·라운드 대기 중 리더보드 중앙 하단의 `게임 종료하기`를 누르면 즉시 그때까지의 점수로 최종 순위를 표시한다.
- 참여자는 대기실·경기·결과 화면에서 나갈 수 있다. 대기실에서 나가면 명단에서 제거하고 재참여할 수 있다. 경기 중 나가면 추가 제출을 막되 획득 점수·콤보·문제 시간을 보존하며, 같은 프로필로 코드를 입력해 재입장할 수 있다.
- 힌트·콤보·속도 보너스는 혼자 하는 모드와 같은 `scoring.js`를 사용한다. 서버에서 문제를 처음 제공한 시각부터 속도를 재며 클라이언트가 보낸 속도·가산점을 사용하지 않는다. 힌트를 보면 기본점수만 50% 적용한다. 믹스도 실제 문제 난이도의 기본점수로 계산한다.
- 팀 추가·제거 시 기존 상자들이 이동·크기 변경과 함께 바운스하고 새 상자는 옆에서 들어온다. 감소한 상자는 짧게 사라진다. 순위·크기 변경에도 이동 애니메이션을 적용하며 동작 줄이기 설정을 따른다.
- 참여 QR은 공용 공유 위젯의 QR 창을 재사용한다. 이동·크기 조절·위치 초기화·핀 기능이 같으며, 대항전 QR에는 블러가 없다. 핀 고정 시 배경 클릭·Escape로 닫히지 않고 닫기 버튼으로 닫을 수 있다.
- 양 모드에서 `audio.js`를 공유해 상단 SOUND ON/OFF가 배경음악과 기존 효과음 설정을 동기화한다. 게임 중에만 반복 재생하고 결과·라운드 대기·숨겨진 탭에서는 멈춘다. 음원은 Kevin MacLeod의 `Exit the Premises`(신시사이저·타악기, 128 BPM, Driving/Intense)이며 공식 CC BY 4.0 조건을 확인했다. 출처는 `public/spell-drill/audio/LICENSE.txt`와 화면의 BGM 링크에 표시한다. 공식 MP3를 128 kbps(약 3.36 MB)로 변환해 자체 제공한다.
- 점수·정답·제출 중복·제한 시간·권한은 서버에서 판정한다. 방 상태와 서명 키는 클라이언트 접근이 차단된 Firestore 컬렉션에 저장한다. 방은 24시간 만료되며 `expiresAt` TTL로 삭제된다.

## 로컬 실행 및 배포

```sh
cd server/spell-battle
npm ci
npm start
```

`http://localhost:47820/spell-drill/`. 로컬 실행은 메모리에 방을 보관하고 브라우저 프로필 확인을 로컬에서 수행한다. 재시작하면 방과 세션이 초기화된다. Google 로그인은 ID 토큰을 확인한다.

클라우드 소스 준비(명시한 출력 폴더에 생성):

```sh
node scripts/build-spell-battle-context.mjs ~/Downloads/Codex/verification/spell-battle/cloud
gcloud run deploy spell-drill-battle --project parcyun --region asia-northeast3 --source ~/Downloads/Codex/verification/spell-battle/cloud --service-account spell-battle@parcyun.iam.gserviceaccount.com --allow-unauthenticated --min-instances 0 --max-instances 3 --memory 512Mi --cpu 1 --concurrency 40 --timeout 60
```

런타임 서비스 계정은 Firestore 접근용 `roles/datastore.user`만 사용한다. `public/game-account.js` 하단의 `psBattleIdentity`는 기존 계정 확인 기능을 공유한다. 문장 데이터는 기존 Spell Drill의 `SENTENCES`에서 생성하므로 수정 시 API도 재배포한다.

## 검증 및 남은 확인

- 도메인·스토리지 테스트 9개와 점수·브라우저 프로필·공용 QR 회귀 검증을 포함한 관련 테스트 43개 통과. 서버 힌트 감점·속도 측정·콤보 배율·10초 간격·재입장·중도 종료 점수 보존을 포함한다.
- 실제 로컬 UI: 프로필 생성, 팀전·개인전 방 생성·참여, 10개 팀 2행, 드래그, 팀 이름, 준비, 점수 제출, 리더보드 순위 이동, 종료 결과, 모바일 레이아웃 확인.
- 실제 Cloud Run: Firebase 임시 계정으로 팀전·개인전 입장·권한·준비·시작·정답·중복 방지·종료·QR·CORS 확인. 개인전에는 팀이 없고 동일 난이도·종료 시간을 적용하며 개인 점수가 독립 집계됨을 확인했다. 테스트 방과 임시 계정 삭제 완료.
- Astro 빌드 통과. 전체 테스트 중 기존 연락 API 의존성 미설치와 홈 Dexterity 링크의 편집 ID 누락은 대항전 범위 밖이며 변경하지 않았다.
- 2026-11-17 대기실 후속 검증: 대항전·브라우저 프로필 관련 테스트 10개 통과. 23명 명단으로 320×568·390×844·844×390에서 전체 화면 넘침 없이 목록만 스크롤, 대기 커서 0개, 참여자 설정 제거·박스 클릭 무동작·준비 체크·스크롤 위치 유지·나가기·재참여·진행자 종료 확인 및 참여자 종료 안내를 실제 UI에서 확인했다.
- 라이브 API에서도 진행자 외 종료 거절, 나가기 응답·명단 제거·대기실 재참여, 종료 전파·닫힌 코드 재참여 거절, 경기 중 나간 개인의 점수 보존과 추가 제출 거절을 확인했다. 검수 계정과 방은 삭제했다.
- 후속 종합 검증: 실제 로컬 UI에서 음악 반복 재생·음소거 동기화·결과 정지, 공용 QR 핀·배경 클릭·블러 없음, 팀 추가·제거 이동과 크기 바운스, 힌트→3콤보×1.5·LIGHTNING·개인전 하단 카드 없음→재입장 점수 유지→10초 카운트→2라운드→진행자 중도 종료 순위를 확인했다. 실제 Cloud Run에서도 Firebase 검수 계정으로 같은 점수·시간·재입장·종료 규칙을 검증하고 방과 계정을 삭제했다.
- 미검증: 실제 휴대폰 카메라로 QR 참여, 실제 Google 로그인 팝업 경로, 여러 학급 동시 부하. 다음 확인: 라이브에서 진행자 1명과 참여자 2명으로 한 경기 진행한 뒤 기기별 QR·로그인을 확인한다.
