# Spell Drill 대항전

2026-11-17 라이브 구현. 정적 화면은 기존 GitHub Pages 배포를 사용하고 방 API는 Cloud Run `parcyun / asia-northeast3 / spell-drill-battle`을 사용한다. API 주소는 `public/spell-drill/battle/config.json`에 있다.

## 동작

- 브라우저 프로필 또는 Google 로그인 확인 후 입장한다. 라이브 API는 Firebase ID 토큰을 검증하고 6시간 유효한 대항전 세션을 발급한다. 한 방에서 인증 계정·브라우저 프로필 식별자가 일치하면 기존 참가 프로필에 다시 연결한다. 별도의 서버 프로필을 만들지 않고 방 입장 시 별명·사진을 스냅샷으로 보관한다. 전역 랭킹의 브라우저 프로필 버전 구분은 변경하지 않는다.
- 게임을 만들 때 팀전과 개인전을 선택한다. 진행자는 플레이어에 포함되지 않는다. 팀전은 2~10개 팀을 설정하고 참여자는 인원이 적은 팀 중 무작위로 배정된다. 진행 전 팀 이동·내보내기·팀 수·난이도·시간·라운드를 설정한다. 이동한 사람은 팀 목록 맨 아래로 간다.
- 개인전에는 팀 정보·팀 이동·팀 이름이 없다. 개인전 대기실·리더보드·결과는 프로필 사진과 닉네임 중심의 개인 카드다. 전원이 같은 난이도·시간·라운드로 플레이하며 개인별 점수와 순위를 집계한다. 일반 리더보드 카드는 약 60px, 1위는 약 86px로 줄였다.
- 팀의 첫 번째 참여자가 팀 이름을 바꾼다. 준비 완료한 참여자의 카드는 잠기고 팀원 전원이 준비하면 팀 이름도 잠긴다. 설정이 바뀌면 준비가 취소된다. 참여자 두 명 이상, 전원 준비 후 시작한다.
- 진행자는 실시간 리더보드, 참여자는 답안 화면을 본다. 개인전 풀이 화면 하단에는 내 점수 카드를 반복 표시하지 않으며, 참여자 결과 화면에는 다른 플레이어 목록을 표시하지 않는다. 순위 변경 시 카드가 이동하며 1위는 큰 호박색 카드다. 라운드 사이 10초 카운트다운 후 새 라운드 점수는 0점으로 시작한다. 최종 결과에서 완료한 라운드 점수를 합산한다. 경기 중 종료하면 진행 중 라운드 점수도 한 번만 합산한다.
- 팀 상자는 상단 강조선 없이 테두리와 내부 배경색으로 구분하고, 순위가 바뀌어도 팀별 색을 유지한다.
- 준비 전 참여자 이름 박스는 정상 색으로 보이는 비상호작용 요소이며, 준비 완료 시 초록 체크와 비활성 색을 표시한다. 이름 옆 이동 화살표와 대항전 내부의 대기 커서를 제거했다. 진행자는 준비 전 이름을 눌러 관리하거나 드래그로 이동한다.
- 대기실은 브라우저 높이에 맞춘 고정 상단·하단과 독립된 목록 스크롤 영역으로 구성하며 스크롤바를 숨긴다. 참여자에게 상단 게임 설정을 표시하지 않는다. 명단 갱신이나 준비 상태 변경 시 목록 스크롤 위치를 보존한다.
- 준비 화면·리더보드의 참여 코드는 상단바 중앙에 표시한다. 진행자는 대기실 중앙 하단의 `대항전 종료하기`에서 확인 후 방을 닫으며, 참여자에게 종료 안내를 표시하고 기존 코드 재참여를 막는다. 경기·라운드 대기 중 우측 하단의 `게임 종료하기`를 누르면 그때까지의 라운드 점수를 합산해 최종 순위를 표시한다.
- 참여자는 대기실·경기·결과 화면에서 나갈 수 있다. 나간 프로필은 연결 끊김 상태로 남겨 재입장 시 기존 자리·사진·점수에 연결한다. 새로고침은 계정별로 저장한 방 코드에서 자동 복구한다. 연결이 끊기면 준비 완료를 해제하고 끊김 아이콘·비활성 색을 표시한다. 복구 후 다시 준비 완료를 눌러야 한다. 페이지 종료 신호와 마지막 응답 기준 12초 만료를 함께 사용하며, 단순히 다른 탭으로 이동하는 것은 즉시 끊김으로 처리하지 않는다.
- 서버는 같은 인증 계정 또는 기존 브라우저 프로필 식별자에 해당하는 중복 참가를 막고, 이미 저장된 중복 행도 읽을 때 정리한다. 중복 점수는 합산하지 않고 높은 값을 보존한다. 프로필 버전·익명 인증 갱신 이력은 방 내부에 최대 16개씩 보관하며 API의 참가자 목록에는 노출하지 않는다. 사진은 최대 48px WebP 썸네일로 요청 본문에 전달하고 서명된 해시와 대조한다. 이미지 본문을 인증 헤더에 넣지 않는다.
- 힌트·콤보·속도 보너스는 혼자 하는 모드와 같은 `scoring.js`를 사용한다. 서버에서 문제를 처음 제공한 시각부터 속도를 재며 클라이언트가 보낸 속도·가산점을 사용하지 않는다. 힌트를 보면 기본점수만 50% 적용한다. 믹스도 실제 문제 난이도의 기본점수로 계산한다.
- 오답은 연속 횟수에 따라 10·20·30점씩 감점하고 정답 시 오답 연속 횟수를 초기화한다. `PASS`는 매 라운드 3회로 시작하고 사용 횟수에 따라 10·20·30점씩 감점한다. 획득 점수 누계가 1,000점 늘 때마다 패스 1회를 지급한다. 모든 규칙은 혼자 하는 모드의 공통 함수를 서버에서 호출하며 0점 아래로 감점하지 않는다. 힌트 버튼은 붉은색 `HINT`로 표시한다.
- 대항전 하단 푸터의 설명 문구를 제거하고 브랜드 서명·BGM 출처만 표시한다.
- 팀 추가·제거 시 기존 상자들이 이동·크기 변경과 함께 바운스하고 새 상자는 옆에서 들어온다. 감소한 상자는 짧게 사라진다. 순위·크기 변경에도 이동 애니메이션을 적용하며 동작 줄이기 설정을 따른다.
- 참여 QR은 공용 공유 위젯의 QR 창을 재사용한다. 이동·크기 조절·위치 초기화·핀 기능이 같으며, 대항전 QR에는 블러가 없다. 핀 고정 시 배경 클릭·Escape로 닫히지 않고 닫기 버튼으로 닫을 수 있다. 공용 QR과 같은 Dexter 캐릭터를 이미지 중앙에 직접 포함하고 오류 복원 H·여백 4모듈을 적용한다. 480·240·192px에서 120개 디코딩과 실제 서버 QR의 192px 디코딩을 확인했다.
- 양 모드에서 `audio.js`를 공유해 상단 SOUND ON/OFF가 배경음악과 기존 효과음 설정을 동기화한다. 스펠 드릴 전체에서 첫 조작 후 재생하며 숨겨진 탭에서는 멈춘다. Kevin MacLeod의 전자음악 연주곡 5곡을 순서대로 반복하며 공식 CC BY 4.0 조건을 확인했다. 출처는 `public/spell-drill/audio/LICENSE.txt`와 화면의 BGM 링크에 표시한다. 공식 MP3를 128 kbps로 변환해 자체 제공한다.
- 점수·정답·제출 중복·제한 시간·권한은 서버에서 판정한다. 방 상태와 서명 키는 클라이언트 접근이 차단된 Firestore 컬렉션에 저장한다. 방은 24시간 만료되며 `expiresAt` TTL로 삭제된다.

## 로컬 실행 및 배포

```sh
cd server/spell-battle
npm ci
npm start
```

`http://localhost:47820/spell-drill/`. 로컬 실행은 메모리에 방을 보관하고 브라우저 프로필 확인을 로컬에서 수행한다. 재시작하면 방과 세션이 초기화된다. Google 로그인은 ID 토큰을 확인한다.

클라우드 소스 준비(명시한 출력 폴더에 생성):

```sh
node scripts/build-spell-battle-context.mjs ~/Downloads/Codex/verification/spell-battle/cloud
gcloud run deploy spell-drill-battle --project parcyun --region asia-northeast3 --source ~/Downloads/Codex/verification/spell-battle/cloud --service-account spell-battle@parcyun.iam.gserviceaccount.com --allow-unauthenticated --min-instances 0 --max-instances 3 --memory 512Mi --cpu 1 --concurrency 40 --timeout 60
```

런타임 서비스 계정은 Firestore 접근용 `roles/datastore.user`만 사용한다. `public/game-account.js` 하단의 `psBattleIdentity`는 기존 계정 확인 기능을 공유한다. 문장 데이터는 기존 Spell Drill의 `SENTENCES`에서 생성하므로 수정 시 API도 재배포한다.

- 프로필·재접속 후속 검증: 실제 브라우저 네트워크 차단→호스트 끊김 표시→복구 후 준비 해제→새로고침 자동 재입장→중복 카드 없음, 프로필 사진 로딩, 상단바 코드·우측 하단 종료, 1라운드 210점→2라운드 0점→최종 합산 420점, 참여자 결과 목록 없음까지 확인했다. 실제 Cloud Run에서도 동시 재입장 8건을 하나의 프로필로 유지하고 원래 별명·사진·점수를 보존했다.
- 미검증: 실제 휴대폰 카메라로 QR 참여, 실제 Google 로그인 팝업 경로, 여러 학급 동시 부하. 다음 확인: 라이브에서 진행자 1명과 참여자 2명으로 한 경기 진행한 뒤 기기별 QR·로그인을 확인한다.

## 2026-11-17 플레이 흐름 후속 변경
- 내보낸 계정도 다시 참가할 수 있다. 경기 중 새 참가자는 다음 라운드까지 대기하며 답안·힌트·패스를 서버에서 막는다.
- 최초 시작은 3초 준비 카운트 후 진행하며, 대기·최종 결과 화면 전환은 페이드 처리한다. 라운드 사이 숫자를 갱신할 때 화면을 재생성하지 않는다.
- 배경음악은 사이트 전체에서 사용자 첫 조작 후 재생한다. CC BY 4.0 음원 5곡을 순차 무한 반복한다.
- 준비 완료해도 진행자는 팀 이동이 가능하다. 팀 상자 안의 플레이어 목록을 독립 스크롤하고 스크롤 중 재렌더를 미뤄 제스처를 보존한다.
- 팀전 플레이 화면은 내 점수를 함께 표시하며 데스크톱 우측에 점수순 팀원 목록을 표시한다. 모바일에서는 해당 목록을 숨긴다. 진행자는 종료 후 다시하기로 기존 팀을 대기실로 되돌린다.
