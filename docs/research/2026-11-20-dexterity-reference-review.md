# Dexterity: 실제 개인 블로그·스튜디오 레퍼런스 검토

확인일: 2026-11-20(KST). 목적: 사진 중심 기록과 서비스 가이드북을 함께 담는 Dexterity의 최소 개선 판단. 화면 재설계·코드 변경·배포는 하지 않았다.

## 결론

현재의 사진 갤러리와 좁은 본문 폭은 유지하는 편이 맞다. 개인 블로그에서 가져올 것은 **글을 고르는 정보와 읽은 뒤의 다음 동선**, 스튜디오에서 가져올 것은 **선별한 이미지와 짧은 맥락 설명**이다. 대형 포트폴리오의 복잡한 필터·전면 영상·스크롤 연출은 지금 필요하지 않다.

## 확인 방법과 한계

- agent-reach의 공개 Jina Reader 경로로 아래 7개 운영 사이트(개인 4·스튜디오 3)의 본문·링크 구조를 직접 읽었다. 로그인·쿠키·계정 연결·브라우저 조작은 사용하지 않았다. 출처는 모두 사이트 운영자의 1차 자료다.
- 확인한 것은 현재 응답의 콘텐츠·정보 구조다. 실제 픽셀 배치, 호버·모션, 모바일 터치, 성능·전환율·접근성 통과 여부는 **미검증**이다. 아래 적용 판단은 이를 토대로 한 설계 추론이다.
- 개인이 자기 이름으로 운영하는 사이트임은 확인했지만 모든 코드를 혼자 작성했는지까지 증명하지는 않았다. Josh Comeau는 극단적 미니멀 블로그가 아니라 기능이 많은 비교 사례다.
- 로컬은 `src/pages/dexterity/index.astro`, `hyangmisa.astro`, `guidebook/[service].astro`, `src/components/DexterityControls.astro`, `src/data/dexterity.ts`, `public/dexterity.css` 및 `docs/DEXTERITY.md`를 읽었다. 지침·코드의 정적 확인이지 현재 라이브 검증이 아니다. 이번 범위에 HWP/PDF/오피스 문서 분석은 없었다.

Lee의 [CSS에 관한 본인 글](https://leerob.com/css)은 자신이 만든 CSS 예제와 도구 선택을 설명한다. 다만 이것만으로 현재 개인 사이트 전체를 혼자 구축했다고 단정할 수는 없다. 과거 사이트 이름의 [공개 저장소 주소](https://github.com/leerob/leerob.io)는 현재 `leerob/next-mdx-blog`라는 템플릿 저장소로 리디렉션되었다. **공개 템플릿은 확인했지만 현재 `leerob.com` 운영 소스와의 동일성 및 현 버전의 단독 구축은 미확인**이다. 나머지 개인 사이트도 이번 확인 범위에서 현재 버전의 단독 구축을 명시하는 근거를 확보하지 못했다. 따라서 ‘개인이 실제 자기 이름으로 운영하는 사이트’와 ‘전부 혼자 코딩한 사이트’를 구분한다.

## 현재 Dexterity: 유지할 강점

- 사진 카드 → 글이라는 단순한 구조. 빈 카테고리는 렌더하지 않으며 정방형 이미지·제목·조회수가 역할별로 나뉘어 있다. 사진 중심이라는 기존 지침과 일치한다.
- 향미사 본문은 텍스트 최대 640px, 사진은 더 넓게 배치한다. 원본 사진 링크, 메뉴판 비자름, 사진 설명, 장소 정보가 있다. 포트폴리오의 이미지 감상과 블로그의 읽기를 함께 제공하는 기반이다.
- 가이드북은 목록 복귀와 다른 가이드북 링크가 이미 있다. 공용 도구 그룹, 키보드 초점 표시·reduced-motion 분기·safe-area 처리가 코드에 있다. 이를 새 프레임워크로 갈아엎을 근거는 없다.
- RSS·작성자·날짜·구조화 데이터도 이미 있다. 다만 RSS는 head의 자동 발견 링크이므로 눈에 보이는 구독 버튼이 있다는 뜻은 아니다.

## 부족한 지점과 최소 권고

P1은 먼저 확인하거나 고칠 신뢰성 문제, P2는 다음 소규모 편집 개선, P3은 콘텐츠 증가 후 검토다. 레퍼런스 미채택 자체를 결함으로 보지 않는다.

### P1 — 테마 버튼 상태 의미 통일

향미사는 초기 dark 상태에서 `aria-pressed="true"`이지만 가이드북은 같은 dark 상태에서 `false`다. 두 버튼은 모두 ‘밝은 화면으로 보기’라는 이름을 사용한다. 정적 코드상 상태 의미가 서로 다르다. 공통 의미를 ‘밝은 화면 켜짐’으로 정한다면 dark=false, light=true로 통일하는 작은 변경을 권고한다. 정확한 읽힘과 실제 토글은 화면낭독기·키보드 검증이 필요하다. 디자인 변경보다 먼저 처리할 수 있다.

### P2 — 향미사 글 끝의 명시적 목록 복귀

가이드북에는 있지만 향미사 본문 끝에는 없다. 상단 로고로 복귀는 가능하므로 막힌 경로는 아니다. 장소 카드·좋아요/공유 아래에 `← 카페 기록` 한 링크를 추가하는 정도가 최소안이다. 새 추천 시스템은 불필요하다. 완료 기준: 하단에서 키보드 한 경로로 해당 카테고리 목록에 복귀.

### P2 — 가이드북 카드의 선택 정보

데이터에 description이 있으나 목록은 제목과 조회수만 표시한다. 시각적인 게임 썸네일만으로 가이드의 실제 용도가 불명확할 가능성이 있다(설계 추론). 우선 가이드북에만 기존 설명을 짧게 노출하는 안을 비교한다. 사진 글 전체에 부제·날짜·태그·통계를 한꺼번에 붙이지 않는다. 완료 기준: 사진과 제목을 가리지 않고 모바일에서 서비스 용도를 알 수 있음.

### P2 — 카테고리 위치 표식의 터치 탐색 검증

현재 우측 고정 표식은 선으로 보이고 이름은 hover/focus 때 나타난다. 접근성 이름은 있지만 터치 사용자는 이름을 보기 전에 목적지를 알아야 하는 부담이 있을 수 있다(추론). 먼저 실기기에서 카테고리 이동을 확인하고, 필요할 때만 상단에 현재 존재하는 분류의 짧은 텍스트 링크를 제공한다. 표식은 기존 사용자 요청과 연결되므로 조사만으로 제거하지 않는다.

### P3 — 아카이브·구독·필터 확장

텍스트 아카이브는 여러 달의 기록이 누적되어 ‘찾기’ 문제가 생길 때 추가한다. 가시적인 RSS 링크는 정기 발행 의도가 있을 때 푸터 한 링크면 된다. 검색·태그 클라우드·인기순·더보기 페이징·뉴스레터·댓글 복원은 현재 필수 항목이 아니다. 좋아요는 현 브라우저 선택이므로 타인의 총 공감 수처럼 표현하지 않는다.

## 권고 실행 범위

가장 작은 다음 묶음은 **테마 상태 통일 → 향미사 목록 복귀 → 가이드북 설명 한 줄 검토**다. 사진 자르기·본문·가격·지도·조회 집계·브랜드·공용 도킹은 이번 조사만으로 바꾸지 않는다. 적용 시 관련 테스트와 320/390/1440px 검수, 키보드·실기기 공유/지도/탐색을 분리해 확인해야 한다. 이 문서는 변경 제안이며 구현 완료 보고가 아니다.
