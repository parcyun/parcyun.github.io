# 서비스별 리뷰·기능 개선 요청 설계

## 목표

리뷰와 기능 개선 요청을 서비스 단위로 분리하고, 리뷰 공감·정렬·목록 스크롤 힌트와 관리자 태그·상태·삭제 기능을 추가한다. Design Studio에서 저장한 페이지 문구는 이후 코드 배포에도 유지되어야 한다.

## 서비스 분류

- 각 항목은 단일 `service_key`를 가진다.
- 지원 키와 관리자 표시명은 다음으로 제한한다.
  - `home`: 메인 홈
  - `spell-drill`: 스펠드릴
  - `atlas-gears`: ATLAS GEARS
  - `geoweb`: GeoWeb
  - `other`: 기타
  - `unclassified`: 미분류
- 기능 개선 요청은 제출 경로를 서버에서 정규화해 `service_key`를 저장한다.
- 공용 푸터의 리뷰 링크는 현재 서비스 키를 쿼리로 전달한다.
- 리뷰 페이지는 전달받은 서비스 키로 리뷰를 작성하고 같은 서비스의 공개 리뷰만 조회한다.
- 출처가 없던 기존 리뷰는 `unclassified`로 마이그레이션하며 공개 서비스 목록에는 노출하지 않는다. 관리자가 태그를 지정하면 해당 서비스에 노출한다.
- 클라이언트에서 전체 목록을 받은 뒤 숨기지 않는다. 공개 조회 RPC가 서비스 키로 필터링해 다른 서비스의 데이터를 반환하지 않는다.

## 공개 리뷰

- 리뷰에 브라우저 로컬 식별자를 이용한 공감 토글을 추가한다. 개인정보, IP, 로그인 정보는 저장하지 않는다.
- 목록은 `like_count DESC, created_at DESC` 순으로 정렬한다.
- 같은 브라우저가 같은 리뷰에 한 번만 공감할 수 있으며 다시 누르면 취소한다.
- 공개된 리뷰만 공감할 수 있다.
- 목록은 최대 50개를 조회하되 화면은 약 10개 높이로 제한해 내부 스크롤한다.
- 스크롤바는 숨긴다.
- 9개 이상이면 목록 하단에 콘텐츠 색상으로 자연스럽게 사라지는 페이드 그림자를 표시한다. 끝까지 스크롤하면 페이드를 제거한다.

## 기능 개선 요청

- 제출과 공개 조회 모두 동일한 서비스 키를 사용한다.
- 기존 공감 기능을 유지한다.
- 공개 목록은 현재 서비스 항목만 반환한다.
- 기존 `source_path`는 감사와 관리자 확인을 위해 유지하며 서비스 키 자동 분류의 입력으로 사용한다.

## 관리자 기능

- 리뷰와 기능 개선 요청 카드에 서비스 태그를 표시한다.
- `태그 수정` 버튼을 누르면 고정된 서비스 태그 목록에서 하나를 선택해 저장한다.
- 리뷰와 기능 개선 요청 모두 영구 삭제 버튼을 제공한다. 삭제 전 브라우저 확인을 거친다.
- `pending` 항목에만 승인 버튼을 표시한다.
- 승인된 항목은 버튼 대신 `published` 텍스트를 앰버색으로 표시한다.
- 반려·보류 동작은 기존 기능을 유지한다.
- 리뷰 카드에는 공감 수도 표시한다.

## 페이지 문구 배포 안전성

- Supabase의 저장 문구를 최종 원본으로 취급한다.
- 정적 HTML 문구는 DB 오버라이드가 없을 때만 사용하는 기본값이다.
- DB 문구와 디자인 값이 모두 로드되기 전에는 Design Studio 저장 동작을 허용하지 않는다.
- 편집 대상은 DOM 순서가 아니라 작성된 고정 ID로 식별한다.
- 배포·새로고침·미리보기 로딩 과정에서는 DB 값을 생성·갱신·삭제하지 않는다.
- 사용자가 명시적으로 `기본값으로 초기화`한 경우에만 해당 DB 오버라이드를 삭제한다.

## 데이터베이스 인터페이스

기존 RPC를 서비스 키 인자로 교체하거나 확장한다.

- `submit_review(rating, body, service_key, voter_id)`
- `list_reviews(service_key)`
- `toggle_review_like(review_id, voter_id)`
- `submit_feedback(body, source_path, author_id, service_key)`
- `list_feedback(service_key)`
- `admin_set_review_service(password, review_id, service_key)`
- `admin_set_feedback_service(password, feedback_id, service_key)`
- `admin_delete_review(password, review_id)`
- `admin_delete_feedback(password, feedback_id)`

관리자 목록 RPC는 `service_key`, 표시용 태그, `like_count`를 함께 반환한다. 모든 새 테이블은 RLS를 활성화하고 직접 접근 권한을 제거하며, 공개 역할에는 필요한 RPC 실행 권한만 명시적으로 부여한다.

## 오류 처리

- 허용되지 않은 서비스 키는 서버에서 거부한다.
- 리뷰·기능 개선 요청을 찾지 못한 관리자 변경·삭제는 오류로 처리한다.
- 공감 식별자 길이와 공개 상태를 서버에서 검증한다.
- 공개 조회 실패 시 현재의 오류 메시지를 유지하며 다른 서비스 데이터로 폴백하지 않는다.

## 검증

- 서비스 A에서 작성·승인한 리뷰와 요청이 서비스 B 조회 결과에 포함되지 않는다.
- 미분류 기존 리뷰는 공개 목록에서 제외되고 태그 지정 후 해당 서비스에 나타난다.
- 리뷰 공감 추가·취소와 공감 수 우선 정렬을 검증한다.
- 승인된 카드에는 승인 버튼이 없고 앰버 `published`가 표시된다.
- 관리자 태그 변경과 삭제가 리뷰·요청 모두에서 동작한다.
- 10개 높이의 숨김 스크롤과 9개 이상 하단 페이드, 스크롤 끝 페이드 제거를 브라우저에서 확인한다.
- 기존 기능 개선 요청 공감·검열·승인 흐름과 전체 Astro 빌드가 통과한다.
- DB에 저장한 페이지 문구가 빌드·새로고침 뒤에도 유지되며 초기화 동작만 DB 값을 삭제한다.
